# Fitness Tracker（食事と筋トレの記録 API）

筋トレの記録と、毎日の食事の記録を、1つの API でまとめて管理するための作品です。
食事は、日本食品標準成分表の約2,500食品から選んで記録でき、栄養は自動で計算されます。

現在は API のみで、画面はありません。動作の確認は、FastAPI が自動で作る /docs の画面から行えます。

## 作った理由
筋トレの記録アプリと食事の管理アプリは別々のものが多く、両方を使い分けるのが手間だった。
1つの場所で記録して、その日の食事と筋トレをまとめて見られるようにしたかった。

## 主な機能
- 筋トレの記録：種目・重量・回数・セット数を記録する（1日の分をまとめて送れる）
- 前回の記録の取得：種目ごとに、一番最近の日の記録を取り出せる（入力の手間を減らすため）
- 食品の検索：成分表の約2,500食品から、名前で検索できる（複数の言葉で絞り込み）
- 食事の記録：朝食・昼食・夕食・間食ごとに、食品とグラム数を記録する。栄養は自動で計算
- 1日のまとめ：その日の合計カロリーと PFC（食事の区分ごとの内訳つき）、種目ごとのセット数・総挙上量・最大重量

## 使っている技術
- Python / FastAPI / SQLite / pytest

## 動かし方（Windows / PowerShell）

1. リポジトリを clone する

```
git clone https://github.com/kurotaka411/fitness-tracker.git
cd fitness-tracker
```

2. 仮想環境を作って、ライブラリを入れる

```
py -m venv .venv
.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
```

3. 成分表の Excel をダウンロードして、`data` フォルダに置く
   - 文部科学省「日本食品標準成分表（八訂）増補2023年」のページから、本表の「第2章（データ）（Excel）」をダウンロードする
   - `data` フォルダを作り、その中に置く（`.xlsx` が1つだけの状態にする）

4. 取り込みのスクリプトを実行する

```
py scripts/import_foods.py
```

5. サーバーを起動して、/docs を開く

```
fastapi dev app/main.py
```

ブラウザで http://127.0.0.1:8000/docs を開く

## テストの実行

```
py -m pytest
```

API・取り込みの値の変換・1日のまとめなど、28件のテストがあります。

## API の一覧

| メソッドとパス | 内容 |
|---|---|
| `GET /foods?keyword=...` | 食品を名前で検索する（最大20件） |
| `POST /meals` | 食事を記録する（複数の食品をまとめて） |
| `GET /meals?date=...` | その日の食事の一覧（食品名と栄養つき） |
| `PUT /meals/{meal_id}` | 食事の記録を1品修正する |
| `DELETE /meals/{meal_id}` | 食事の記録を1品削除する |
| `POST /workouts` | 筋トレを記録する（セット数の分だけ展開して保存） |
| `GET /workouts?date=...` | その日の筋トレの一覧 |
| `GET /workouts/latest?exercise=...` | その種目の前回の記録 |
| `PUT /workouts/{workout_id}` | 筋トレの記録を1セット修正する |
| `DELETE /workouts/{workout_id}` | 筋トレの記録を1セット削除する |
| `GET /summary?date=...` | その日の食事と筋トレのまとめ |

送るデータ・返すデータの形や、エラーの条件などの詳細は、[design.md](design.md) にまとめています。


## 設計で工夫したこと
### 筋トレは「1行＝1セット」で保存し、入力はまとめて送れるようにした
最初は「重量・回数・セット数」を1行にまとめる形で考えていたが、
実際のトレーニングでは、セットごとに重量や回数を変えることが多い。
そこで、保存は1行＝1セットにして正確に記録できるようにし、
同じ重量・回数のセットは「sets」でまとめて送れるようにした。
保存する形（正確さ）と入力する形（楽さ）を分けて考えた。

### 食事の記録は「全部保存するか、何も保存しないか」のどちらかにした
複数の食材を入力し、ある食材でエラーが出たとする。
利用者はエラーが出たので、直して複数の食材をまとめてもう一度送信する。
もし、複数の食材を送信するときにエラーが出たものだけをはじいてその他を保存する作りにすると、正常だった食材が二回記録されてしまうので、実際より多く計算されてしまう。
そこで、1品でもエラーがあれば何も保存しないようにした。
エラーのときは何も記録されていないので、利用者は直してもう一度送るだけでよい。
この動きは、エラーの後に記録が0件であることをテストで確かめている。
